## What is still missing

A recoverable optimizer loop does not make a whole job bounded. Evaluation,
generation, reference scoring, retried work, export and scratch storage can all
consume resources outside an update count. Existing owned-worker controls prove
cooperative cleanup and hard per-file limits, not arbitrary-descendant containment
or a hard aggregate filesystem quota.

The campaign's `updates × microbatch × accumulation × length` geometry is not
total forward work. In the current DPO runner, each selected pair supplies chosen
and rejected branches to both policy and reference. At100 updates, accumulation4
and maximum sequence length512, the declared204,800-position geometry does not
cover the possible408,800 scored input positions per network,817,600 combined,
even before evaluation, generation or replay. These are source-derived logical
upper bounds, not measured model-scale costs. Activation recomputation during
backward is additional dispatch work not counted by these logical forwards.

RLVR's training response slots likewise exclude uncached growing-prefix forwards,
old-policy scoring, reference/current rescoring and evaluation. A token cap does
not establish total compute. Keep valid sampled tokens, padded/attempted slots,
scored positions, calls and unknown failed-call work distinct.

## Safe source implementation order

1. **Nonexecuting stage compiler.** Accept only fixed campaign stage IDs and
   constrained branch-specific fields. Bind the current runner/interpreter,
   parent/input/lock/source bytes, numerical/evaluation contract, budgets and
   independently retained approval/prerequisite references. Produce a preparation
   record, not a subprocess. Reject arbitrary argv/shell strings, injected paths,
   unknown IDs and a bare `approved: true` supplied by the record itself. Never
   fabricate human authority or convert null external outcomes to completed rows.
2. **Multidimensional work reservation.** Reserve a whole known next operation
   before collection, forward or optimizer application. Include baseline/final
   evaluation, old/reference scoring and generation under explicit bounds.
   Bind limits, cumulative counters, reservations and remaining capacity to
   completed/pending snapshots. A resumed invocation must not reset its budget.
   Retain failed/retried attempts, label successful/attempted/unknown costs, and
   refuse a crossing update rather than shortening its objective or dropping
   inconvenient data. Logical work is not a FLOP or dispatched-backward guarantee.
3. **Cooperative artifact reservation.** Give snapshots, markers, logs, exports
   and scratch explicit byte/entry limits with exclusive ownership. Account for
   partial writes and retained failures; reserve peak coexistence of old/new
   checkpoints rather than counting only final files. A bounded writer covering
   cooperative outputs is useful, but cannot enforce a physical aggregate quota
   on arbitrary library/child writes. Fail closed where that backend is required.
4. **Backend interfaces and preflight.** Specify private containment, bounded
   observers, external watchdog and actual GPU-idle/ownership probes. Mock refusals,
   incomplete inspection, races and cleanup in CPU tests. Preserve25GiB host
   reserve; a per-job cgroup cap does not guarantee global availability against
   unrelated jobs. Do not kill conflicts or modify existing session/user groups.
5. **Current preparation revision.** Bind new guard/snapshot/compiler dependencies
   and correct the old preparation source's DPO “no verified resume CLI” note.
   Record verified tiny CPU recovery separately from pending pretrained/profile
   recovery. Keep the frozen45-row campaign and original outcomes unchanged.

Acceptance before a source gate passes: original-equation parity, whole-operation
