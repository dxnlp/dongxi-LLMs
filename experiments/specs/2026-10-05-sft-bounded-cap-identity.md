# Bounded SFT cap identity and closing verification

This narrow premeasurement addendum closes an identity-reader gap without
changing the SFT objective, original full and LoRA recipes, cached generation,
snapshot format or cumulative work ledger. The preceding `run-01` result remains
historical: its 61 controls and four numerical replay arms passed, but generic
input hashing could reopen a cap replaced by a no-peer FIFO after the initial
bounded read. Its successful observations do not establish the new gate.

## Fixed identity rule

The work-cap file must not enter `collect_run_identity`'s generic input-file
reader. At both production identity observations, retain an explicit
`bounded_work_limits` role containing the lexical absolute path, exact byte
count and SHA256 from the bounded nonblocking no-follow regular-file reader.
Require the observed bytes to match the original parsed bytes, and recompute
the enclosing identity digest after attaching the role. Train, development,
template and recovery input hashing remain unchanged.

Before checkpoint export and before claiming completion, use the same bounded
reader to compare the role with the retained identity and original parsed byte
digest. Do not substitute a generic digest function at either closing gate.
Changing a cap path to a FIFO, symlink or different regular bytes must fail
without tokenizer or model acquisition, and must retain the original file and
failure record in the authored controls. This is a trusted-local cooperative
check, not atomic protection against a hostile actor between system calls.

arms. Extend the controls with exact role and enclosing-digest assertions,
replacement immediately before initial generic identity collection, and a
no-peer FIFO at the cap-only closing gate. Check both changed regular bytes and
FIFO replacements; assert that the generic collector never receives the cap
path and that no loader is called. Use deadline-bounded subprocess controls
