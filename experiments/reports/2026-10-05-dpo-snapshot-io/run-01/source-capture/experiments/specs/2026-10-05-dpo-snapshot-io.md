# DPO snapshot inspection and save accounting

This specification precedes collection. It adds the shared snapshot I/O hook to
the actual DPO runner without changing its objective, original reference,
sampling, checkpoint mode or nineteen-dimensional model/semantic work caps.
It is a trusted-local CPU source gate, not a production authorization, physical
quota, hostile-checkpoint sandbox or pretrained/CUDA/BF16 result.

## Independent admission

The production CLI requires an explicit, separate nine-dimensional v1 snapshot
I/O contract and journal. Resume additionally requires a bounded independently
retained work receipt, scientific contract, payload SHA and byte count. Both the
I/O and original nineteen-dimensional journals bind their independently retained
prefixes before shared inspection or model allocation, retaining later failed
charges. The actual constructed model/reference/optimizer contract must still
equal the retained science contract before state application.

Resume payloads, markers, contracts, receipts and caps are excluded from generic
identity file hashing. Bounded metadata identities and independently expected
payload bytes are recorded separately; only a successfully admitted shared
inspection is labeled measured payload verification. Repeated metadata checks
must not reopen the payload through a generic hasher.

Each actual inspect/load/save uses the optional shared I/O hook. Hooked snapshots
use schema two and explicit work receipts; unhooked schema-one CPU controls stay
valid. Receipt prefixes precede save reservation. The physical journal retains
the subsequent save completion, which cannot be serialized inside its own
payload. Actual load compares both carried prefixes to the independently retained
receipt before runner semantics or application. Callback and restore still cost
separate original semantic panels.

Artifact restoration/inventory occurs only after journal admission. Its sealed
file hashes, caller state capture, bounded bootstrap metadata, journal integrity,
identity of other source/input/parent files, allocation and application remain
outside the nine shared-operation dimensions. No claim of all payload reads,
CPU operations, aggregate output storage or physical containment is permitted.

2. Refuse exhausted inspect/load before full payload reads, hashing,
   `torch.load`, finite checks, callback or application. Refuse save before

   payload/runner prefixes match the separately retained receipt. Preserve an

   expected-versus-measured identity distinction, and no model construction
