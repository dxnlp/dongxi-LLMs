## Independent receipt before payload inspection

The [runner](../../scripts/run_chapter11_spark_dpo.py) requires a separate full
nine-dimensional v1 I/O contract with an explicit whole-operation envelope and
private persistent journal. Resume requires `--resume-io-receipt` in addition to
the independently supplied payload SHA/bytes, science contract and original
model-work/artifact identities. There are no default I/O capacities, appended
training dimensions or automatic schema upgrades.

The bounded receipt binds the snapshot header, science hash, I/O contract hash,
payload-carried I/O prefix and runner-work prefix. Both physical journals open
against those independently retained prefixes before shared inspection. Their
full later histories remain charged. Pending or beyond-endpoint DPO receipts,
changed contracts, copied journals and mismatched prefixes refuse before payload
work. The actual parent/reference/model/optimizer contract is recomputed after
construction and must match before artifact restoration or state application.

Generic identity input hashing no longer includes the resume payload, marker,
contracts, receipts or caps. Metadata uses the bounded64KiB no-follow regular
reader and retains actual byte identities. The payload expectation is recorded
as expected, not measured. A separate measured field appears only after actual
admitted shared inspection verifies the payload bytes. Repeated identity checks
do not silently reopen the payload through a generic hasher.

The [CLI controls](2026-10-05-dpo-snapshot-io/run-01/cli-ordering-controls.json)
use mocked platform/interface observers, actual physical journals and actual
shared inspection. With inspection capacity zero, the payload verifier, artifact
inventory and model backend are not called. With capacity available, inspection
completes and its measured identity is published before one mocked model backend
call deliberately raises. No actual CUDA or pretrained model is loaded; these
spies prove ordering, not real Spark readiness or interface provenance.

## Save and load preserve three different histories

Every initial/periodic/final save uses the shared I/O hook. Hooked snapshots have
schema two and a separately retained work receipt; the legitimate unhooked
schema-one CPU reference remains available. Accounted science cannot silently
omit the save hook. The receipt captures the I/O prefix immediately before save
reservation. Its physical journal retains the later save completion: a payload
cannot serialize the future completion of its own serialization.

The original nineteen-dimensional semantic callback and restore are still
separate charged panels. Commit carries its own completed semantic charge before
the I/O save starts. Actual load verifies both carried prefixes against the
independent receipt before calling runner semantics. Resume restores the numerical
cursor but refunds neither later I/O nor model-work spending. The shared writer
also reserves the additional64KiB receipt pathname inside the existing artifact
envelope; payload/marker/staging and later partial files remain retained.

Repeated actual inspect/load calls each consume capacity. Exhausted inspect/load
refuse before shared byte verification, deserialization, callback or application.
Exhausted save refuses before the shared tree/clone/serializer, leaving its prior
semantic panel spent. The joint artifact control seals three work receipts and
accounts for ten retained entries including its journal.
