# Story work implementation boundaries

The persistent story contract counts declared model operations while preserving
the historical loss, accumulation, optimizer, stream and native observer
equations. It does not migrate the story checkpoint to the shared snapshot
format. Data preparation, selection, tokenization, source and payload hashing,
metadata processing, serialization, cloning, backward checkpoint recomputation
and physical resources remain outside these units.

The accounted Session reserves initialization before the global seed or model
allocation. An update gathers its original complete accumulation group, checks
the existing successful-target cap, then reserves exact model-call positions and
valid labels before LR, gradient, mode or parameter changes. A refused reservation
restores the stream. A failed entered update retains its ticket and poisons the
Session; every observation, update and save then refuses. Restore uses a fresh
Session and the same journal, including later failed spending.

Policy-forward counters include training and evaluation only. Generation uses
the native six greedy/sample branches, real EOS, private seed909 and uncached
prefix lengths. Its conservative full-panel ceiling remains charged after early
EOS. Manual activation panels are separate because they do not call the LM head.
Entered calls, successful calls and uncertain remaining work are retained
separately. Save/restore counters count operation attempts, not byte admission.

Accounted saves retain the prefix before their own reservation, publish a new
payload without overwrite, then fsync an exclusive independent receipt. The
receipt binds the payload digest/size, complete cursor, science and saved prefix.
A partial receipt is not repaired or treated as a recovery point. Recovery binds
the same physical journal before hashing/loading the payload. Restricted loading
and additional preapplication checks do not claim a general hostile-payload
sandbox. The original unaccounted tensor loader remains explicitly distinct.

The CLI accepts paired `--work-limits` and `--work-journal`, plus
`--resume-work-receipt` for accounted recovery. The limits file is the full strict
contract, not a partial cap map. It is read and rechecked through a bounded
nonblocking no-follow metadata reader. The journal is closed on every exit.
Accounted fresh runs save completed0 before the first observer; unaccounted
default argument arities and publication order remain unchanged. A failed
initial observer therefore has a durable cursor and retains its panel spending.

## Development checks

Before any new acceptance collection, the declared21-dimension schema and API
were added to the premeasurement protocol. A syntax check of the three owned
source files exited 0. The existing unchanged story pipeline, target-cap and
mocked launcher panel then passed 34 tests in 0.796s, exit 0. This is developmental
compatibility evidence, not the later independent acceptance collector and not
an external launch. The launcher controls mocked refusal paths; no GPU, corpus
acquisition or training service was started.

The live Session also anchors its original journal identity so replacing its
public hook with a newly created same-science journal cannot refill its allowance.
The loaded prefix is strictly validated in addition to comparison with the
independent receipt, and a returned nonfinite loss records its completed forward
call before refusing backward. These source hardenings precede final collection.

The final metadata gates additionally require native stream boundary order,
measured position provenance, supported dense scalar Adam clocks, and unchanged
live model/recipe/data/device/target cap. Accounting cannot be attached after
unaccounted initialization. Resume path/inode aliases against fixed bootstrap
roles and bounded manifest-declared additional inputs are refused before their
bodies are hashed. The actual source glob used by run metadata is included too.
The original metrics-before-save order remains: a numerical metric row is not
a durable checkpoint or an embedded full numerical history.

Two attempted notes patches failed their exact-text verification and changed no
file. The corrections were applied from the reread text. These were editorial
patch diagnostics, not failed model jobs. The independent development controls
and their source-drift diagnostic are retained by the separate test collector;
only the later source-frozen collector may support final acceptance.

Before final measurement, a narrow additional guard made loss-call admission
one-shot. The native update/evaluation arms a permit after entering the policy
units; it binds the active ticket and the actual input/label objects. The loss
method consumes the permit before calling the model, and operation cleanup clears
it. An unrelated admitted save operation, an outside loss call or a duplicate
callback loss call cannot reuse it. Private internals and raw Module calls remain
outside cooperative runner accounting; this is not a Python execution sandbox.
