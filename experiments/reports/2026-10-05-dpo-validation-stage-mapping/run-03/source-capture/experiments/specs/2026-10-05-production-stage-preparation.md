# Nonexecuting production stage preparation

This specification precedes the new compiler measurements. The compiler will
turn one of the existing45 campaign stage IDs into a source-bound preparation
record, never a command or launch. It closes part of the source preparation gap,
not production containment, authority, training or capability evidence. The
learner remains Day9; every actual external campaign outcome stays null.

## Fixed recipes and observed files

Freeze the existing45 IDs as an explicit allowlist. Reject missing, renamed or
extra IDs even if a future campaign function supplies them. Derive branch,
stage, parent slots, numerical declarations and evaluation contract only from
the current authored campaign, never request-supplied argv or overrides. Bind
current compiler, runner, guard, snapshot and lock bytes. The old October4
specification and reports retain their historical source identities.

Preparation records name the original story trainer, actual SFT/DPO/RLVR source
or the relevant evaluation/merge source. Stages without a complete current
adapter remain explicitly blocked. In particular, the existing service-oriented
story launcher is not the new production launcher, and chosen-only SFT must not
be relabeled DPO or full SFT. No record contains executable argv or shell text.

Only an independently configured artifact root and inventory may supply local
file bindings. Inventory paths must be relative, bounded, regular, no-follow
files under that root. Expected byte lengths and SHA256 are independently
provided and checked against actual read bytes. Fixtures use authored data,
parent metadata and tokenizer-interface JSON, not pretrained checkpoint files.
They cannot establish a model's compatibility or actual checkpoint genealogy.

## Receipts do not create authority

A compile request contains exactly a stage ID. Receipt names, expected hashes,
expected lengths, artifact root and receipt root are separate trusted inputs.
Read strict bounded JSON with duplicate-key, unknown-field, nonfinite-number,
type and symlink rejection. Reject self-approved booleans, shell/argv fields,
arbitrary request paths, missing or changed receipts and substituted stage IDs.

The approval receipt binds the complete preparation digest and stage. Every
required predecessor has an independently pinned prerequisite receipt binding
its own stage, preparation, result and parent/input observations. The preflight
receipt binds the same preparation, an independently expected observation nonce,
an explicit observation-time/freshness contract and five ready backend gates:
private containment, aggregate artifact quota, bounded observers, external
watchdog and GPU clearance. Missing or stale gates fail closed.

The implemented positive path accepts only `authored-local-fixture` receipts.
It reports `production_ready=false`, `launch_authorized=false` and zero jobs.
These authored assertions test binding/schema behavior, not real consent,
cryptographic issuer authentication, live probes or platform capability. Actual
production receipt scope remains unsupported rather than being promoted from
self-attestation. No actual backend/service/GPU probe is exercised here.

## Work ceilings and current loop boundaries

Keep valid training targets separate from padded input positions, generated
response slots, growing-prefix positions, policy/reference scoring, evaluation,
replay and backward recomputation. Report source-derived logical envelopes,
not observed FLOPs or dispatched work. DPO's two chosen/rejected branches each
run through policy and reference; the100-update, accumulation4, length512
recipe has possible408800 scored positions per network, not204800 total.
RLVR response slots do not bound growing-prefix/scoring/evaluation work.

Require finite typed ceilings for elapsed time,25GiB-or-greater host reserve,
artifact bytes/entries/per-file/snapshot size and each work dimension. Unknown
evaluation/resource obligations or a missing stage adapter remain blockers.
The preparation compiler does not enforce these caps inside a training loop or
provide a physical quota. The DPO runner separately has cooperative whole-job
reservation CPU controls; mapping the compiler declarations into its14-dimension
ledger, covering the other runners and proving a real physical backend remain
separate integration gates.

isolated Python binary is23323176 bytes, larger than the4MiB source read limit.
Preserve that diagnostic, not as a numerical recipe change. Before recollection,
distinguish a32MiB interpreter hashing envelope from unchanged1MiB fixture files,

receipts. This changes no stage, approval, backend or scientific recipe.

Use the existing isolated CPU Python with hidden CUDA and offline Hugging Face
settings. Run this module's unittest controls, the existing campaign tests and
the root-owned mocked preflight controls. The new compiler starts no process or
model. Existing campaign regression tests may run only their original bounded
self-owned leaf CPU children; no service/cgroup/model worker, acquisition or
installation is authorized. Positive controls construct original tiny JSON files and
explicitly authored receipts in a new temporary directory.

Before collecting the final reference, freeze source/test/spec bytes. Retain
exact invocation, Python/platform/package identity, test output and actual exit,
all before/after hashes, preparation identities and negative outcomes. Controls
cover all45 recipes, deterministic source-bound preparation, no spawning,
valid-parent/interface binding, strict receipt/hash/freshness validation, missing
backends, unknown IDs/fields/paths, bool and nonfinite ceilings, actual file
mutation/symlinks and source/lock changes. A new source revision requires a new
verification record; do not overwrite a failed collection.

The final report must distinguish passing fixture preparation from unresolved
platform containment/quota, real stage approval, acquisition, pretrained recovery,
Spark profile/pilot, language evaluation, Mac and hosted execution.
