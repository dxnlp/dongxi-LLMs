# Tokenizer contracts: worked reasoning

Use [the notebook](05_tokenizer_contracts.ipynb) for predictions and runnable
references. The implementation wraps the existing teaching `ByteBPE` in
[`tokenizer_contracts.py`](../../../src/dongxi_llms/tokenizer_contracts.py).

1. With the repeated five-character record `ab cd`, whole-record training
   merges across the space and emits one ID. The declared word/space rule emits
   three IDs. Both decode to the same text; their model-facing sequences differ.
2. Recognition admits reserved strings as controls before ordinary BPE runs.
   Longest-match recognition chooses the doubled `<STOP><STOP>` marker, and
   ordinary merges never contain its bytes. Rejection is a distinct input
   policy. These authored strings do not reproduce a production chat template.
3. Independent records `gar` and `den` cannot use the learned whole `garden`
   merge. Joint chunks can. Both decode correctly, so an ID-stream comparison
   catches the framing error. Chunk mode buffers one complete record and has
   an explicit optional character limit; it is not an unbounded streaming claim.
4. NFC normalizes decomposed `cafe` plus an acute accent to `café`.
   Serialization binds learned pieces, merge order and boundary policies to a
   content hash. Strict decoding rejects a lone incomplete UTF-8 byte;
   replacement decoding explicitly loses its original identity.
5. Equal text probability 0.25 yields token perplexities 4 and 2 under one
   versus two tokens, while the fixed one-byte text receives two bits in either
   case. Two bits for `a` plus four bits for the three-byte `數` give six bits
   over four bytes, or 1.5 bits/byte. Averaging document rates gives 1.6667 and
   overweights the shorter record. Context, normalization, masks, EOS and the
   exact raw spans must agree before comparison.

These are exact boundary and arithmetic references, not measurements of a
pretrained language model. Plots are regenerated by the adjacent notebook cells.
