52,000 examples and a few hundred dollars

In March 2023, a team at Stanford trained Alpaca, a model that answers instructions, starting from Meta's LLaMA 7B. LLaMA 7B had only been pretrained: it predicts the next word.

The team didn't change the architecture or add new knowledge. They used 52,000 examples, each made of an instruction and a response.

OpenAI's text-davinci-003 generated the examples, for less than $500. Training took 3 hours on 8 GPUs, for less than $100. In a small blind comparison run by the team, Alpaca and text-davinci-003 were preferred almost equally often: 90 to 89.

[IMAGE 01]

Alpaca also gave wrong answers. Asked for the capital of Tanzania, it answered Dar es Salaam. The capital is Dodoma.

The examples taught the model how to answer. They didn't teach it which facts are true.

Why does a small set of examples change a model's behavior this much, yet leave its factual errors in place? This article starts from that question and covers the first post-training technique: instruction tuning, also called supervised fine-tuning (SFT). It is the second article in our post-training series.

Same loss, a different task

Instruction tuning keeps the pretraining objective. At every position the model predicts the next token, a cross-entropy loss measures how far the prediction is from the correct token, and training raises the probability of the correct token.

What differs is the data and the task. Pretraining uses raw text, and the task is continuation. Instruction tuning uses pairs, each an instruction and a response, and the task is to produce the response for the instruction.

Same loss, different data and task: pretraining learns to continue text, instruction tuning learns to answer instructions.

It is called supervised because every input comes with a designated target output. Who wrote the data doesn't matter. Pretraining text is written by people too, and Alpaca's examples were all generated by a model, yet they count as supervised data.

What instruction tuning changes

A base model has already learned a great deal during pretraining: facts, grammar, code, many writing styles. Its default behavior, though, is to continue the input. Given a question, it may write more questions.

Instruction tuning changes how the model behaves:

  • It responds to the request instead of continuing the input.
  • It follows the format the instruction asks for, such as a list, a single word or a translation.
  • It separates user and assistant turns in a conversation.
  • It stops generating when the answer is complete.
  • It declines some requests, if the examples include refusals.

Two studies show the character of this change.

LIMA (2023) fine-tuned a 65B LLaMA model on only 1,000 curated examples, with no reinforcement learning. In the authors' human evaluation, 43% of its answers were rated equal to or better than GPT-4's. The authors conclude that almost all of a model's knowledge comes from pretraining, and that a small amount of instruction data mainly determines how it answers.

[IMAGE 02]

FLAN (2021) rewrote more than 60 NLP tasks as natural-language instructions and fine-tuned a 137B model on them. On tasks absent from training, it outperformed the 175B GPT-3 in the zero-shot setting on 20 of 25 tests.

[IMAGE 03]

Instruction tuning therefore teaches a general ability to follow instructions, which transfers to tasks not seen in training. That is why it is the first step of post-training: the model first learns to answer instructions, and preference alignment and reinforcement learning then improve the quality of those answers.

The training recipe

Instruction tuning has five steps:

  1. Collect pairs of instructions and responses.
  2. Format each pair as a conversation-shaped token sequence with the model's chat template.
  3. Mask the sequence with a loss mask, so that only the response contributes to the loss.
  4. Train with the next-token loss, usually with a small learning rate for a few epochs. Either all parameters are updated (full fine-tuning), or the original parameters are frozen and a small number of added parameters are trained (LoRA, the topic of the next article).
  5. Evaluate on tasks that did not appear in training.

[IMAGE 04]

Steps 2 and 3 contain most of the details, covered below.

One example in three forms

Stored form: a conversation made of messages, each labeled with a role (system, user, assistant).

Input form: the chat template joins all messages into one token sequence and inserts special markers. In Qwen's template, each turn starts with <|im_start|> and the role name, and ends with <|im_end|>.

Training form: the loss mask marks which tokens of the sequence contribute to the loss. The model reads the whole sequence, but only the marked tokens count.

Which tokens get a loss

There is one criterion:

Compute the loss only on tokens the model must generate when it is used.

Applied to each part:

  • User message: no loss. The model reads it but never generates it. A loss here would train the model to generate user questions.
  • Assistant header <|im_start|>assistant: no loss. At inference time the application writes it into the prompt.
  • Response: loss.
  • Closing <|im_end|>: loss. This is how the model learns when to stop. Without it, the model may keep generating after the answer, even producing the next user turn.
  • Line break after <|im_end|>: no loss. Generation has already ended.

[IMAGE 07]

As a formula, with mₜ = 1 if position t contributes to the loss and 0 otherwise:

loss = − (1 / number of loss tokens) × Σₜ mₜ · log p(correct next token at position t)

Positions without loss contribute zero, and the average is taken over loss positions only.

Masked tokens are still trained

The loss mask decides which predictions count toward the loss. It doesn't change which tokens attention reads. The response depends on reading the prompt, so the gradient from the response's loss flows back through attention to the prompt tokens and updates the parameters that process them.

[IMAGE 08]

Masked tokens get no loss, but they still take part in training.

The one-position shift

The model's output at position t is a prediction for position t + 1, so the loss pairs each prediction with the token one position later. In PyTorch:

cross_entropy(logits[:-1], labels[1:], ignore_index=-100)

Here -100 marks positions without loss.

Without the shift, the shapes still match and the code runs, but each prediction is paired with the token at its own position, and the model learns to copy the current token.

[IMAGE 09]

Before training, decode the loss tokens and read them. They should contain only the responses and their <|im_end|> markers.

Where the data comes from

Instruction data has three main sources:

  • Written by people: volunteers or annotators write instructions and responses. Quality is high, and so is cost.
  • Converted datasets: simple templates turn existing translation, question-answering or sentiment datasets into instructions, for example: Did the reviewer enjoy the movie?
  • Generated by models: a language model writes instructions and responses, usually followed by filtering or review. This is the most common source today.

Data quality has a large effect. In one study, adding 500 safety examples to a large instruction dataset clearly reduced the rate of harmful answers.

Length matters when mixing data. The loss is averaged over loss tokens, so longer responses take a larger share: a 500-token response weighs about 250 times as much as a 2-token response. A mix should therefore be balanced by token count, not only by number of examples.

What instruction tuning can and cannot do

It can, at low cost, teach a model to answer instructions, follow formats, separate conversation roles, stop at the right point and decline some requests, and this transfers to new tasks.

It cannot:

  • Reliably add knowledge. Alpaca's wrong capital shows that the model learned the form of an answer without gaining knowledge. It can also learn to answer questions it cannot answer in the same assured form.
  • Go beyond its training data. The model imitates the examples, including their errors.
  • Compare answers or judge correctness. Each example provides one reference response, so the model cannot learn which of two reasonable answers is better, or whether a long solution reaches the right result.

The last point is handled by the next two techniques. Preference alignment learns from comparisons between answers. Reinforcement learning with verifiable rewards (RLVR) learns from whether an answer is correct.

Reasoning models follow the same order: they are first instruction-tuned on written-out solutions, which teaches the format of step-by-step reasoning, and then reinforcement learning raises how often the reasoning reaches correct answers.

Summary

  • Instruction tuning continues training with the pretraining loss, on pairs of instructions and responses.
  • It is called supervised because each input has a designated target output, regardless of who wrote it.
  • It mainly changes how the model behaves and adds little knowledge; a small amount of data has a large effect and transfers to new tasks.
  • The loss covers only tokens the model must generate: the response and its closing <|im_end|>. Masked tokens still take part in training.
  • It imitates reference answers but cannot compare them or check them; the later stages of post-training do that.
