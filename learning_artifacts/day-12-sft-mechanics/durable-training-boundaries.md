## The distinction worth carrying between machines

A weights file can recreate a forward model. A resumable completed boundary
also preserves Adam moments, random streams, data selection, cumulative work,
scientific identity and the numerical metric describing that boundary. The
independently retained expected byte receipt and contract are inputs to recovery;
an unchecked marker cannot authenticate itself. Output locations and invocation
IDs can change, but schedule/objective/token meanings cannot silently change.

If update 3 changes weights but fails to commit, replay starts at durable update 2.
If update 3 commits and metric append then fails, recover its saved metric and
start with update 4. Keep failed invocation attempts; do not count retried update
numbers as extra successful steps. A readable marker after failed directory
fsync establishes visibility, not confirmed durability.

DPO must also preserve its original reference. Copying the already updated
policy as a replacement reference resets the relative comparison and changes
the objective. RLVR adds a different pending phase: policy/Adam remain at the
completed boundary, while source cursor and collection RNG have advanced and
the retained pool is awaiting application. The actual RLVR loop now passes
completed/pending CPU replay with no resampling; pretrained/CUDA/BF16 and
production resource integration remain separate gates.
